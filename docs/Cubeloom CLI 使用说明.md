# Cubeloom CLI 使用说明

> 面向不想开浏览器、直接在终端里导入结构的场景。终端交互版，不依赖网页管理端。

## 启动方式

**方式一：双击（推荐）**
```
<解压目录>\cubeloom-cli.bat
```

**方式二：命令行**
```powershell
cd <解压目录>
node cli.mjs
```

启动后进入主菜单：

```
════════════════════════════════════════════
   Cubeloom CLI v1.0 · 基岩版结构导入
════════════════════════════════════════════
主菜单
   1. 启动 / 重启 WS 服务
   2. 导入结构文件
   3. 查看运行状态
   4. 完整性检查（快速）
   5. 完整性检查（深度）
   6. 补建缺失方块
   7. 取消当前导入
   8. 发送游戏指令
   9. 执行沙箱代码
  10. 查看最近日志
  11. 停止 WS 服务
   0. 退出
```

## 典型流程

1. 选 `1` 启动 WS 服务（首次启动约 3–10 秒，会自动等待端口就绪）
2. 游戏里输入 `/connect ws://127.0.0.1:11451`
3. 选 `2`，粘贴结构文件路径（支持 `.mcstructure` / `.litematic` / `.schem` / `.schematic` / `.nbt`，可直接拖文件进窗口）
4. 回车确认 Y 偏移 → 自动上传解析并开始导入
5. 界面会实时显示 `百分比 / 已放方块 / 当前阶段`，结束后提示是否全部通过
6. 有缺口时选 `6` 补建，或选 `5` 深度检查
7. 完事选 `11` 停止服务、`0` 退出

## 配置

首次运行会在程序目录生成 `cubeloom-cli.json`：

```json
{
  "wsPort": 11451,
  "adminPort": 11452,
  "controlPort": 11453,
  "offsetY": 0,
  "lastFile": ""
}
```

- `wsPort`：游戏连接端口（游戏内 `/connect` 用）
- `controlPort`：CLI 与主程序通信的本机控制端口
- `offsetY` / `lastFile`：上次使用的 Y 偏移与文件，导入时会作为默认值

改端口时注意：`wsPort` 改了，游戏内 `/connect` 的地址也要跟着改。

## 和网页管理端的关系

- 两者功能等价，都是控制同一个 WS 服务
- CLI 启动的服务与网页端启动的服务是同一个进程模型，**不要同时启动两个**（端口会冲突）
- 已开网页端时，CLI 选 `1` 会提示「WS 服务已在运行」并直接复用

## 常见问题

| 现象 | 处理 |
|---|---|
| `找不到 tsx` | 在程序目录执行 `npm install` |
| `控制接口不可用` | WS 服务没启动，先选 1 |
| 游戏 `/connect` 连不上 | 确认服务在运行、端口和游戏内地址一致、防火墙放行本机端口 |
| 导入提示失败 | 选 `6` 补建；仍失败选 `5` 深度检查 |
| 中文乱码 | 用 `cubeloom-cli.bat` 启动（内部已 `chcp 65001`）；或手动 `chcp 65001` |

## 文件

| 文件 | 说明 |
|---|---|
| `cli.mjs` | CLI 主程序（Node 直跑，无需编译） |

| `cubeloom-cli.json` | 首次运行生成的配置 |
