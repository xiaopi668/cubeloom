# 参考：《星月导入器 1.0.5》里值得借鉴的点

来源：用户提供的 `星月导入器1.0.5.zip`（Go 源码，7481 个文件）。它是面向网易版**租赁服**的建筑导入/导出工具，
机器人进服后用协议层批量放置，并带自己的 `chunk_fill` 规划器。这里只记录思路，不复制代码。

## 它的关键设计

| 点 | 做法 | 我们是否已采用 |
|---|---|---|
| 3D 合块 | `chunk_fill/internal/native/fill.go`：从每个未处理格子出发，按 **6 种轴向顺序**各长一次，取体积最大（同体积取「维度更多」即更方的） | ✅ 0.2.6 |
| 体积上限 | `maxFillVolume = 32766`（`/fill` 含端点计数，32768 会被拒） | ✅ 0.2.6 |
| 特殊方块 | `IsSpecialPlacementBlockName`：沙/砂砾/混凝土粉末、火把、铁轨、门、告示牌、作物、藤蔓、珊瑚等**不参与 fill/clone**，逐块放且排在实心块之后 | ✅ 0.2.6（分类表 + 自下而上 setblock） |
| 区域化推进 | `-region N` = **N×N 个区块**（默认租赁服 5，即 80×80 方块；联机大厅/本地联机 1），按区域加载/放置，避免一次跨太多区块 | ⏳ 未做 |
| 增量速度 | `-speed` 命令/秒（租赁服默认 2000，联机大厅 300） | 部分（我们按回执限速，可加显式速率） |
| 大厅/本地联机默认关 fill | `-usefill` 在联机大厅/本地联机默认 false —— 这两类会话对批量指令更敏感 | ⏳ 可作默认策略 |
| 任务与缓存 | 任务文件 + token.fsm 缓存 + auth_server.txt 缓存 | 我们有 session.json / sauth.json，思路一致 |

## 还能继续借鉴的两件事

1. **按区块区域推进**：把命令按 16 方块区块分组，每组放之前把机器人 `/tp` 到该区域中心；能显著降低「区块未加载导致 fill 只放了一半」。
   我们现在的做法是「曼哈顿距离 > 16 就 `/tp @s`」，对超大 fill 仍可能跨很多区块。
2. **克隆优化**：它支持 `/clone` 把重复结构复制过去（`clonePlan`），只对平坦/重复区域启用。实现成本高，收益取决于建筑类型，暂不做。

## 与我们的差异

- 它走**协议层**直接写世界（bedrock-world-operator），我们用**原版指令**（setblock/fill）经机器人执行；协议层快但风控更敏感、实现重。
- 它面向租赁服；我们还要覆盖联机大厅/本地联机（PE 通道），那边对批量指令更保守，默认体积可以更小。
