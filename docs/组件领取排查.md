# 联机专区组件领取：501 的真相与正确链路

> 调查日期 2026-11-15，测试账号：PC uid `9555•••87`（昵称已隐去）／PE entity `3102•••735`。
> 目标房间：联机大厅房间 `72563`（entityId `4691878942147351937`），绑定 `res_id = 4659475350398889607`。
> 文中所有 token / sauth 均已脱敏，只保留长度和尾部 4 位。

## 一句话结论

**501 是「你这个账号（PE entity）没拥有这间房绑定的联机专区商品」**，不是「房间主人的组件下架」。
联机专区是 **PE 商城商品**（`channel_id=5`），商品归属记在 **PE entity** 上，所以：

| 动作 | 接口 | host | 用哪套凭据 |
|---|---|---|---|
| 查专区商品的归属/封面 | `/item-channel/query/search-item-channel-list-by-id`（`channel_id=5`） | `g79apigatewayobt.minecraft.cn` | PE |
| 领取联机专区 | `/pe-purchase-item/` | `g79mclobt.minecraft.cn` | PE |
| 进房 | `/online-lobby-room-enter` | `g79apigatewayobt.minecraft.cn` | PE |
| 取服务器地址 / 退房 | `/online-lobby-game-enter`、`/online-lobby-room-enter/leave-room` | `g79apigatewayobt.minecraft.cn` | 用进房成功的那套 |

PC 那条路（`x19apigatewayobt.nie.netease.com` + `/user-item-purchase`）对这类商品**永远**回 `目标找不到`，
因为 PC 商城不卖它。

## 之前一直失败的三个原因

1. **接口选错**：一直用 PC 商城 `/user-item-purchase` 领。联机专区在 PC 商城不存在 → `code=16 目标找不到`。
2. **PE token 早就失效了**：`/pe-authentication` 每成功一次，同账号**之前**的 PE token 立刻作废。
   面板把第一次登录拿到的 `peToken` 存进 `session.json` 就不再更新，之后每次 PE 请求都回
   `您的帐号在另一处登录`——这跟「手机上的游戏占着会话」是一模一样的报错，很容易误判。
3. **归属在 PE 账号上，进房却用 PC 凭据**：即使商品已经领到 PE entity 名下，用 PC 凭据进同一间房**仍然 501**。

第 3 点是最反直觉的一条，也是之前所有排查都卡住的地方。

4. **PE 认证会把同一个账号的 x19 会话挤掉**。做几次 `/pe-authentication` 之后，PC 接口从
   `目标找不到` 变成 `请先登录`，而且 `mode=refresh` 也救不回来（旧 token 已被服务端丢弃）。
   最后确认的恢复办法是**用保存的 sauth 重新登录**（`X19LoginSession mode=sauth` →
   Go 侧 `neteasex19.LoginBySauth`，不需要密码），一次登录同时换新 x19 + PE 两套 token。
   日志原文：
   ```
   [x19login] 查询昵称失败（token 仍然可用）：请先登录
   [x19login] PE 通道认证失败（PC 登录仍然可用）：操作过于频繁，请稍后重试
   [admin] 登录态已刷新：uid 9555•••87，PE 通道就绪（uid 3102•••735）
   ```
   另外 `/pe-authentication` 自己有登录频控：短时间内登录十几次就回
   `操作过于频繁，请稍后重试`。所以 PE 保鲜期设成 30 分钟 + 按需刷新，不要无脑重登。

## 证据链（脱敏后的关键请求/响应）

### 1) 商品是 PE 商城的

`POST https://g79apigatewayobt.minecraft.cn/item-channel/query/search-item-channel-list-by-id`
body `{"channel_id":5,"item_id_list":["4659475350398889607","4688187130037072536"]}`（PE 凭据）

```json
{"code":0,"entities":[
  {"item_id":"4659475350398889607","channel_id":"5","status":"1","buy_state":0},
  {"item_id":"4688187130037072536","channel_id":"5","status":"1","buy_state":1}
]}
```

同样的查询用 PC 凭据打 `channel_id=11` → `{"code":0,"entities":[],"total":0}`，即 PC 商城没有这个商品。

### 2) 已购专区列表里没有它

`POST https://g79apigatewayobt.minecraft.cn/pe-user-item-purchase`（PE 凭据，
body 抄 VQ `LobbyService.GetPurchasedZonesAsync(isPe:true)`）

```json
{"code":0,"total":1,"entities":[{"item_id":"4688187130037072536","res_name":"超平坦123","first_type":6,"buy_state":1}]}
```

`4659475350398889607` 不在里面 → 确实没领过。

### 3) 用「新鲜」PE token 领，一次成功

`POST https://g79mclobt.minecraft.cn/pe-purchase-item/`（先跑一次 `/pe-authentication` 拿新 token）

```json
{"item_id":"4659475350398889607","expertcomment_info":{...,"buy_path":"首页-联机大厅-详情页:4659475350398889607"}}
→ {"code":0,"entity":{"entity_id":"4691879791582856898","buy_type":0}}
```

再用 `item-channel` 查：`buy_state` 从 `0` 变成 `1`。

错误码（同接口实测）：

| 场景 | 响应 |
|---|---|
| 首次领取 | `code=0` |
| 重复领取 | `code=502 物品已经获得`（VQ 把它当失败，其实等价成功） |
| item_id 瞎填（例如房间号 `72563`/`999999999999`） | `code=16 目标找不到` |
| PE token 被顶掉 | `code=?` + `您的帐号在另一处登录` |

### 4) 领到了，但 PC 凭据进房还是 501

`POST https://g79apigatewayobt.minecraft.cn/online-lobby-room-enter`（**PC** 凭据）

```json
{"code":501,"message":"物品还未获得","entity":null}
```

→ 501 响应体里 **没有** 组件 ID（`entity` 是 `null`），必须从房间列表的 `res_id` 拿。

### 5) 换成 PE 凭据，同一间房立刻进得去

```
/online-lobby-room-enter  (PE)  → {"code":0,"entity":{"room_id":4691878942147352000}}
/online-lobby-game-enter  (PE)  → {"code":0,"entity":{"server_host":"1.95.•••.•••","server_port":11285,...}}
/online-lobby-room-enter/leave-room (PE) → {"code":0}
```

## 代码里对应改了什么

### `src/netease-room.ts`

- 新增错误分类：`PE_SESSION_STALE`（PE token 被顶掉）、`ITEM_NOT_FOUND`（`code=16`）、
  `ITEM_ALREADY_OWNED`（`code=502` 等价成功），以及判断函数 `isPeSessionStaleError` /
  `isItemNotFoundError` / `isAlreadyOwnedError`。
- `purchaseComponentManually()`：**先 PE 商城再 PC 商城**（原来反了）。PE 回「目标找不到」才换 PC；
  502 直接算成功；「另一处登录」立刻抛出、不再换通道白打请求。最多 2 个购买请求。
- `purchasePeRoomComponent()`：`allowCodes:["502","16"]` + 统一错误归一化；
  `pcFallback` 只在 PE 回「参数错误」时用。
- `purchaseLobbyComponent()`：候选 ID 逐个试，靠 `purchaseComponentManually` 做通道选择；
  遇到 PE 失效立刻停手。
- `resolveLobbyAddress()` / `enterPeRoom()` → 新增 `enterLobbyRoom()`：
  **PE 优先，501 再换 PC**（PC 侧专区用得上），取地址/退房跟着成功的那套凭据走。
- 新增 `fetchZoneOwnership()`：`item-channel` + `buy_state`，领之前先判断「已拥有」。
- 新增 `lobbyChannelOrder()` / `credForLobbyChannel()`：通道顺序与凭据映射（可单测）。

### `admin-server.ts`

- `session.json` 增加 `peTokenAt`（v3，向后兼容），记录 PE token 取得时间。
- `refreshCredsWithSauth()`：用保存的 sauth 重登一次，**同时**换新 x19 token 和 PE token
  （带并发去重 + 3 分钟频控冷却；PE 那次没刷出来时清掉旧 PE token，绝不留着当有效）。
- `ensurePeCred()`：PE token 超过 30 分钟主动刷新（引擎/机器人在跑时跳过，避免踢掉在线会话）。
- `withAuthRetry()`：撞到「另一处登录」或「请先登录」自动刷一次再重试（同一次操作只重试一次，
  重试前服务端没有产生订单，不会重复下单）。
- `/api/netease-service/purchase`：查归属 → 已拥有则跳过 → PE 领取 → **自动重试一次进房**，
  返回 `{ ok, itemId, channel, alreadyOwned, retry:{ok,host,port} }`。全程只发一个购买请求。
- `/api/netease-service/session/pe` 复用 `refreshPeCred()`。
- `resolveRoomForPanel()`：联机大厅/本地联机默认用 PE 通道（`channel=pc` 是排查开关）。
- 主流程**仍然不自动领取**：只有用户点「领取组件」才会发购买请求。

### 启动参数（`startNetease`）

联机大厅/本地联机现在用 **PE 的 `--UserID/--MD5Token`** 启动 `Program.exe`（`--g79` 本来就是开的），
和 VQ 的 PE 模式一致（`MKeyService.PeLoginWithSauthAsync` 把 `Account` 整体换成 PE 账号，
`LaunchProgram` 再从 `Account` 取 UserID/Token）。租赁服/山头服仍用 PC 登录态。

### 面板 (`admin/index.html`)

- 领取结果区分「领取成功」和「之前就已经拥有」，并把自动重试进房的 `host:port` 直接显示出来。
- 失败提示指向「登录态」一栏的「PE 通道登录」。
- 登录状态里显示 PE token 是几分钟前刷新的。

## 限流与冷却（踩过的坑）

- `/pe-authentication` 有登录频控。调查过程中连续登录十余次后，网易开始回
  `操作过于频繁，请稍后重试`，而且**实测 20 分钟仍未解除**（16:12 起连续失败到 16:32）。
- 因此代码里：
  - PE token 保鲜期 30 分钟，只在需要时刷新，不做「每次请求前都重登」；
  - 刚重新登录过却拿不到 PE token 时，落盘冷却 20 分钟（`netease-bot/auth-cooldown.json`），
    重启 App 也不会继续撞——每次尝试都会加深惩罚，宁可不试；
  - 引擎/机器人在跑时不主动刷新 PE，避免踢掉正在进行的会话。
- 撞上限流时面板会明确说「PE 通道这次没拿到（网易登录频控）」，不会伪装成「PC 商城找不到」。

## 已知未验证项

- **引擎能否用 PE 凭据进服没有实测**：本机测试环境没有原生引擎产物（`apk` 里 `libcubeloom_engine.so`
  是从旧包注入的，构建脚本会提示「没有原生引擎产物」），所以只验证到 HTTP 层拿到
  `server_host:port`（`1.95.•••.•••:11285`）。如果进服后身份/皮肤异常，优先怀疑
  `--UserID/--MD5Token` 与 `--g79` 的组合，必要时加 `--DisplayNameB64`（VQ PE 模式有）。
- 本地联机房间的 501 不带组件 ID（`entity` 是 `null`），面板只能让用户自己填；官方客户端对这类
  房间也是拿房间号当 `item_id` 去试（VQ `OnPeRoomIdEnterClick`），大概率同样领不到。
